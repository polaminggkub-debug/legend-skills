ทักษะที่ใช้กับงานจริง

จับคู่ AC กับหลักฐานที่ตรวจซ้ำได้

อย่าเขียน ‘ทดสอบแล้ว’ ทับทั้งแผน ผลรัน และข้อจำกัด

ผลที่ฝึกได้ในบทนี้ คุณจะสร้าง evidence row ที่มี AC, assertion, revision, ผล และข้อจำกัด

แยกสี่คำนี้ให้ได้: AC คือสิ่งที่ต้องเป็นจริง, verification คือวิธีตรวจ, evidence คือผลที่เกิดขึ้นจริง, และ completion criterion คือเงื่อนไขที่ agent หยุดขั้นตอนได้

evidence row ที่ใช้ได้ควรมี AC → path/assertion → command or action → revision → result → limitation เช่น “Responses input ถูก scan → request assertion + log metadata → run ที่ SHA นี้ → 400 + rule id → ยังไม่มี production log artifact”

แยกชั้นหลักฐาน
PR body อ้างว่ารัน ≠ check-run สำเร็จ ≠ reviewer ยอมรับ ≠ user journey ใช้งานได้จริง ให้เขียนเจ้าของผลและเวลาทุกครั้งที่เป็นไปได้

OpenHands #8310 แสดงว่ารายงาน eval ต้องมี denominator, config และ missing cases: 169/487 กับ 180/500 ไม่ใช่ตัวเลขชุดเดียวกันที่เอามาเปรียบตรง ๆ ได้

เกณฑ์ตรวจตนเอง
