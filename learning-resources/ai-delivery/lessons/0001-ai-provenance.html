ทักษะที่ใช้กับงานจริง

แยกหลักฐานว่า AI เขียนออกจาก AI รีวิว

อย่าตัดสินจากชื่อ branch หรือสไตล์โค้ดเพียงอย่างเดียว

ผลที่ฝึกได้ในบทนี้ คุณจะจัดหลักฐานแต่ละชิ้นได้ว่า ยืนยัน authorship, ยืนยัน review หรือเป็นเพียงเบาะแส

คำว่า “AI เขียน” ต้องตอบให้ได้ว่า หลักฐานอยู่ตรงไหน และหลักฐานนั้นสรุปได้ไกลแค่ไหน ชื่อ claude ใน branch เป็นเบาะแส แต่ PR ที่เปิดโดย bot บอกได้เพียง workflow ส่วน commit ที่เปิดเผย AI ใน Co-Authored-By และร่องรอย agent ลงมือแก้ตามคำสั่งเป็นหลักฐานประกอบที่ตรวจย้อนรอยได้ ทั้งสองอย่างยังไม่บอกว่า AI เขียนทุกบรรทัด

แยกบทบาทสามอย่างเสมอ: คนหรือ bot ที่เปิด PR, ผู้สร้างข้อความ/commit ตามที่เปิดเผย, และผู้ตัดสินใจ merge ส่วน Greptile, Cursor Bugbot หรือ Codex ที่แสดง review เป็นหลักฐานของ AI review ไม่ใช่หลักฐานว่า AI เขียน patch นั้น

กฎใช้งาน
เขียนเป็น “หลักฐาน → สิ่งที่สรุปได้ → สิ่งที่ยังสรุปไม่ได้” เช่น “commit trailer ระบุ Devin AI → มีการเปิดเผย AI ร่วมเขียน commit นี้ → ยังไม่รู้ว่า AI สร้างกี่บรรทัด”
evidence = source + actor + revision + claim + limit
แหล่งต้นทางหลัก

ลองตอบก่อนดูเฉลย

ถ้าต้องการอ้างว่า AI ร่วมเขียนงานหนึ่งชิ้น หลักฐานแรกที่ควรผูกให้แน่นคืออะไร

เลือกคำตอบหนึ่งข้อ

ลงมือกับงานของคุณ

เลือก PR หนึ่งรายการจากงานที่คุณกำลังดู แล้วเขียนหลักฐาน 2 ชิ้น: หนึ่งชิ้นสำหรับ authorship และหนึ่งชิ้นสำหรับ review พร้อมเขียนข้อจำกัดของแต่ละชิ้น

เกณฑ์ตรวจตนเอง
  • ระบุ URL หรือ revision ที่คนอื่นเปิดตรวจได้
  • บอก actor และบทบาทของเขาอย่างชัดเจน
  • แยกคำว่า “ยืนยัน” ออกจาก “เป็นเบาะแส”
  • เขียนสิ่งที่หลักฐานนั้นยังพิสูจน์ไม่ได้

ถามครูได้เสมอ: ถ้าคำศัพท์หรือหลักฐานชิ้นไหนยังไม่ชัด ให้ถามต่อพร้อมคัดลอกประโยคหรือ link ที่ติดขัด ครูจะช่วยแยกข้อเท็จจริงจากข้อสังเคราะห์ให้
