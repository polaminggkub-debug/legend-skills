ทักษะที่ใช้กับงานจริง

แบ่งงานตามผลส่งมอบและ dependency

งานย่อยที่ดีมีเจ้าของ contract และเกณฑ์จบของตัวเอง

ผลที่ฝึกได้ในบทนี้ คุณจะเปลี่ยน feature ใหญ่เป็นชุดงานที่ส่งต่อกันได้โดยไม่ชนกัน

แบ่งงานตาม ผลส่งมอบ ไม่ใช่แบ่งตามจำนวนบรรทัดหรือชื่อไฟล์อย่างเดียว งานหนึ่งควรตอบได้ว่าใครรับผิดชอบ, ส่งอะไร, ใช้ contract จากไหน, ทำพร้อมงานอื่นได้เมื่อใด และจบเมื่อเห็นอะไร

เริ่มด้วย reproduction/contract แล้วค่อยแยก implementation, UI หรือ integration test ตาม dependency ถ้าสองงานต้องตัดสินใจ interface เดียวกัน ให้ตั้งเจ้าของ contract หนึ่งคน ไม่เช่นนั้นจะได้ patch ที่แต่ละส่วนผ่าน test ของตัวเองแต่รวมกันใช้ไม่ได้

จำไว้

งานย่อยที่แยกตามไฟล์แต่ใช้ contract ร่วมโดยไม่มี owner ยังเป็นงานก้อนเดียวในทางความเสี่ยง

ลองตอบก่อนดูเฉลย

หลักใดเหมาะที่สุดสำหรับใช้แบ่งงาน feature ขนาดใหญ่

เลือกคำตอบหนึ่งข้อ

ลงมือกับงานของคุณ

วาดตารางงานของ feature หนึ่งชิ้นในชีวิตจริง 3–5 แถว โดยใส่ owner, output, dependency และ completion criterion ให้ครบ

เกณฑ์ตรวจตนเอง
  • แต่ละแถวมี output ที่ส่งต่อได้
  • เห็น dependency ระหว่างแถว
  • มี owner ของ contract ที่อาจชนกัน
  • ทุกแถวมีเงื่อนไขจบที่ตรวจได้

ถามครูได้เสมอ: ถ้าคำศัพท์หรือหลักฐานชิ้นไหนยังไม่ชัด ให้ถามต่อพร้อมคัดลอกประโยคหรือ link ที่ติดขัด ครูจะช่วยแยกข้อเท็จจริงจากข้อสังเคราะห์ให้
