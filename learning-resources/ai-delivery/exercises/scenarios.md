# โจทย์ฝึกใช้กับงานใหม่

โจทย์ทั้งหมดสร้างขึ้นเพื่อสอน ไม่มีการกล่าวอ้างว่าเป็น PR จริง

## A — test เขียวคนละ revision

AC กำหนดว่าคลิก submit ซ้ำต้องมี record เดียว Commit a1 มี test ผ่าน Agent แก้ query อีกครั้งเป็น b2 หลัง review แต่แนบผล test a1 แล้วขอ merge

ฝึก: เขียนคำตอบกลับ 3 ประโยคที่ระบุช่องว่าง งานแก้ และเกณฑ์จบ ห้ามตอบแค่ว่า “รันเทสอีกที” ต้องบอกเส้นทางและ revision ที่เกี่ยวข้อง

## B — งานขนานที่แก้ contract ชนกัน

Agent A แก้ API response ให้ price เป็นสตางค์ Agent B แก้ UI โดยคิดว่า price เป็นบาท ทั้งคู่แก้คนละไฟล์และ unit test ผ่าน

ฝึก: จัด ownership ของ contract และกำหนด integration AC หนึ่งข้อ ชี้ว่างานใดสำรวจพร้อมกันได้ งานใดต้องรอ interface

## C — reviewer เสนอ migration แต่ไม่มีผู้ใช้กลุ่มนั้น

Feature ยังปิดอยู่และไม่มี production data Reviewer ขอเพิ่ม migration รองรับ format ที่เพิ่งเขียนบน branch นี้ Agent กำลังสร้าง migration 500 บรรทัด

ฝึก: เสนอข้อมูลที่ต้องตรวจเพื่อพิจารณาว่าต้องมี migration หรือไม่ แล้วเขียนคำตอบ reviewer โดยแยกปัญหาจากวิธีแก้ อย่าเดาว่าไม่มี data จริงจากข้อความโจทย์เพียงประโยคเดียวเมื่อใช้กับงานจริง

## D — เปลี่ยนสองอย่างแล้วดีขึ้น

ผู้ทดสอบเปลี่ยน config และ upgrade driver พร้อมกัน แล้วบอกว่า config ใหม่แก้ freeze ได้แน่นอน

ฝึก: เขียนผลสรุปที่รักษาสิ่งที่สังเกตได้ พร้อมทดลองถัดไปที่จะช่วยแยกสาเหตุ ระบุด้วยว่าการกลับไปใช้ driver เดิมทำได้จริงและเหมาะสมหรือไม่

## Rubric สำหรับครู

ให้ feedback ทีละประเด็น แล้วให้ผู้เรียนแก้คำตอบ จบเมื่อมี outcome, scope, observable และข้อจำกัดชัดตามโจทย์นั้น

- A: ต้องมี evidence ที่ใช้กับ b2 หรือ integrated revision ที่เกี่ยวข้อง รวม regression ของ submit ซ้ำ
- B: หน่วยเงินมีเจ้าของ contract เดียวและตัวอย่างค่าที่ assert ข้าม API/UI ได้; คนละไฟล์ไม่ได้แปลว่าอิสระ
- C: ตรวจสภาพ deployment/data จริงก่อนตัด scope; ถ้าไม่มี target ของ migration ให้ลดงานพร้อมเหตุผล
- D: รายงานผลดีขึ้นหลังชุดการเปลี่ยน พร้อม confounding; การทดลองควบคุมต้องเหมาะกับ environment และต้นทุน

เมื่อทำได้ ให้ใช้ template กับ task จริงหนึ่งชิ้น และให้คนที่รับผลลัพธ์อ่านก่อนเริ่ม implementation
