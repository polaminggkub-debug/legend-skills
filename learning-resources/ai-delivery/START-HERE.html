บทเรียนภาษาไทย 8 ตอน

สั่ง AI ให้ส่งงานที่ตรวจรับได้

เรียนจากวงจรจริงใน GitHub ตั้งแต่แยกหลักฐาน AI, ตั้งเป้าหมาย, แบ่งงาน, เขียน acceptance criteria, เลือกหลักฐาน, รับ review, ตัดสินใจ merge จนถึงตรวจสิ่งที่หลุดหลัง merge

เริ่มแบบสั้นเลือกบทที่ตรงกับงานของคุณ ไม่ต้องอ่านเรียงลำดับ ทุกบทมี quiz, แบบฝึกหัด และเกณฑ์ตรวจตนเอง
อ่าน learning pack ฉบับ Markdown เปิด offline lab
01

แยกหลักฐานว่า AI เขียนออกจาก AI รีวิว

คุณจะจัดหลักฐานแต่ละชิ้นได้ว่า ยืนยัน authorship, ยืนยัน review หรือเป็นเพียงเบาะแส

02

เปลี่ยนคำขอกว้างให้เป็นเป้าหมายและขอบเขต

คุณจะเขียน task brief หนึ่งย่อหน้าที่บอก target, non-target และจุดหยุดได้

เปิดบทเรียน
03

แบ่งงานตามผลส่งมอบและ dependency

คุณจะเปลี่ยน feature ใหญ่เป็นชุดงานที่ส่งต่อกันได้โดยไม่ชนกัน

เปิดบทเรียน
04

เขียน acceptance criteria ให้จับความผิดได้

คุณจะเขียน AC แบบ Given/When/Then พร้อม boundary และ negative case

เปิดบทเรียน
05

จับคู่ AC กับหลักฐานที่ตรวจซ้ำได้

คุณจะสร้าง evidence row ที่มี AC, assertion, revision, ผล และข้อจำกัด

เปิดบทเรียน
06

เปลี่ยน review comment ให้เป็นลูปแก้ที่ปิดได้

คุณจะตอบ reviewer แต่ละ finding ด้วยสถานะและหลักฐาน ไม่ใช่แค่ ‘addressed’

เปิดบทเรียน
07

ตัดสินใจ merge จาก revision ที่จะรับจริง

คุณจะอ่าน head SHA, check status, approval และ merge event แยกกัน

เปิดบทเรียน
08

เรียนจากสิ่งที่หลุดหลัง merge

คุณจะออกแบบ post-merge verification ที่ไม่หยุดแค่ build หรือ manual workaround
