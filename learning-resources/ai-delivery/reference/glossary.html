Reference 01

ศัพท์ที่ใช้ตรงกัน

นิยามสั้นสำหรับอ่าน issue, PR, review และหลักฐานโดยไม่ใช้คำเดียวกันคนละความหมาย

คำหมายถึงคำถามตรวจ
AI provenanceร่องรอยที่บอกว่าใคร/ระบบใดผลิตหรือแก้ contribution เช่น bot actor, session, commit trailerหลักฐานนี้ผูกกับ PR หรือ revision ใด และสรุปได้แค่ไหน?
AI reviewความเห็นหรือรายงานจากระบบตรวจ เช่น Greptile, Cursor Bugbot, Codex หรือ Codecovระบบนี้ตรวจอะไร และเป็นผู้เขียน patch ด้วยหรือไม่?
scopeขอบเขตสิ่งที่งานรับผิดชอบ รวม target, non-target และงานที่เลื่อนไปอะไรต้องเปลี่ยน และอะไรต้องไม่เปลี่ยน?
non-targetกรณี ผู้ใช้ เส้นทาง หรืออุปกรณ์ที่อยู่นอกงานและต้องรักษาพฤติกรรมเดิมมี negative case ที่ตรวจได้หรือยัง?
dependencyสิ่งที่งานหนึ่งต้องได้รับจากอีกงาน เช่น contract, schema, fixture หรือ revisionใครเป็น owner ของ contract และงานนี้เริ่มได้เมื่อใด?
acceptance criteria (AC)ข้อกำหนดพฤติกรรมที่รับได้ก่อนเห็น patch มักเขียนเป็น Given/When/Thenถ้า implementation ผิด test ยังเขียวได้ไหม?
verificationวิธีที่ใช้ตรวจ AC เช่น assertion, command, manual step, benchmark หรือ probeวิธีนี้ตรวจ behavior ที่ AC พูดถึงจริงหรือเปล่า?
evidenceผลตรวจที่เกิดขึ้นจริง พร้อม revision, เวลา, ผู้รัน และข้อจำกัดผลนี้เป็น run จริงหรือเป็นเพียง test plan/คำอ้างใน PR?
revision / head SHAจุดของโค้ดที่ผลตรวจผูกอยู่ ต้องระบุเมื่อ branch มีการ push เพิ่มผลตรวจเป็นของ head ที่จะ merge หรือเป็นของ commit เก่า?
findingข้อสังเกตจาก reviewer ที่มี trigger, behavior ที่ผิด และผลเสียเปิด reproduction หรือ code path ที่ทำให้ finding เกิดได้ไหม?
valid / invalid / deferredสถานะการตัดสิน finding: จริงและต้องแก้ / ไม่จริงพร้อมหลักฐาน / เลื่อนไปพร้อมเหตุผลและ ownerการตัดสินใจมีหลักฐานหักล้างหรือ follow-up หรือไม่?
stale review/checkผลตรวจที่ผูกกับ commit เก่าและอาจไม่ครอบคลุม diff หลัง pushระบบรันใหม่บน final head แล้วหรือยัง?
merge eventเหตุการณ์และ commit ที่บอกว่าโค้ดใดถูกนำเข้า branch เป้าหมายจริงมี merged_at และ merge SHA หรือยัง?
post-merge verificationการตรวจ artifact ที่ผู้ใช้ได้รับกับ consumer/เส้นทางจริงหลัง mergeทดสอบ installer, migration, package หรือ hardware path จริงหรือยัง?
completion criterionเงื่อนไขที่บอก agent ว่าขั้นตอนนี้จบและหยุดได้ โดยทุก AC มีหลักฐานหรือช่องว่างที่ประกาศคนอื่นบอกได้ไหมว่ายังขาดอะไร?
เส้นทางอ่านเร็ว
หลักฐาน AI → เป้าหมาย/ขอบเขต → AC → evidence → review → merge → post-merge
